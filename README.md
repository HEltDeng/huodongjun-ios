# 活动君

面向长沙理工大学的校园活动应用，首期客户端为原生 iOS。长期目标包括活动发现、创建、报名、活动群、扫码签到，以及由老师配置和审核的综测计分。学校与规则应可配置，为后续多学校扩展保留边界。

## 当前阶段（2026-10-23）

用户明确要求先实际操作 Luma 原版、逐页记录交互，再进行功能和界面的对标实现。不能把应用商店介绍页当作完整交互证据，也不能凭猜测添加年龄、身份或权限弹窗。

- 本地 Git 工作分支：`codex/ios-campus-events`。尚未创建远程仓库。
- `ios/CampusEvents/` 中已有早期 SwiftUI 草稿和本机数据模型。它们是在完整原版交互核查之前写的，**尚未完成 Xcode 工程、编译、测试或安装，不代表已完成的复刻版本**。
- 原版交互核查前，暂停扩展推测性界面。现有校园海报与特色功能保留为后续素材，不作为 Luma 原版的样式证据。
- 用户没有可用的 iPhone 真机，已选择使用安卓模拟器查看 Luma 原版。
- 用户选择：**先只准备模拟器，原版中的交互由用户操作**。不得自动使用 ADB 点击、填写、登录或操作 Luma。
- 开发目标仍是 iOS。安卓仅作为原版交互参考，系统权限、分享、照片选择、支付等平台差异必须另外记录。

## 交互取证与实现顺序

1. 准备官方 Google Play 安卓模拟器，由用户安装并操作 Luma。
2. 按实际出现顺序记录首次启动、登录、资料填写、权限、导航、详情、报名、凭证、创建与管理。
3. 每个已观察流程记录输入、按钮、弹窗、成功/失败/空状态、返回方式和对应截图。
4. 只把已核对的交互标记为已确认；安卓与 iOS 的差异单独列出。
5. 建立可编译的 iOS 工程，逐模块实现与测试，再安装到 iPhone 模拟器检查。
6. 原版核心流程对标完成后，再加入长沙理工大学身份、活动群、签到与综测等差异功能。
